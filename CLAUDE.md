# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MTG card price watcher (Japanese printings) on GitHub Pages at
https://paludancode.github.io/MTG-Pricerunner/. Two sources: CardTrader (official API) and
Cardmarket (scraped via Firecrawl). **Three** decoupled workflows, and the page merges two
independent feeds:

- `.github/workflows/update.yml` ("Deploy site") publishes to Pages **only on push to `main`** (UI/source changes).
- `.github/workflows/update-cardmarket.yml` ("Update Cardmarket data") is **`workflow_dispatch` only — no `schedule:`, no `push:`, and don't add one.** Every scrape costs credits, so nothing may start it but a human: the site's "↻ CM" button or Actions → Run workflow. It force-pushes `cardmarket.json` as a single orphan commit to the **`data-cm` branch**. `concurrency.cancel-in-progress` is deliberately **false** (unlike the data workflow): a cancelled run may have spent credits without recording them. There is no keepalive step either — that only exists to stop GitHub disabling *scheduled* workflows.
- `.github/workflows/update-data.yml` ("Update card data") runs on a `2-57/5` cron (GitHub best-effort; empirically fires every few hours, not every 5 min) and force-pushes `data.json` as a **single orphan commit to the `data` branch**. The Pages-hosted page fetches it from `raw.githubusercontent.com/.../data/data.json` — fresh data needs no deploy. The `data` branch is a build artifact: never branch from it or PR into it. In practice the cadence comes from a live cron-job.org pinger hitting the workflow's `workflow_dispatch` endpoint every 2 min — see `docs/external-pinger.md`; the in-repo cron is only a fallback.

(A local Node watcher used to live in `local/`; it was removed in 03c49ae — see git
history if it ever needs resurrecting. Cardmarket support came back afterwards, in the
cloud pipeline, via Firecrawl.)

## Workflow rules (non-negotiable)

- **Never push to `main` directly.** Branch (`feat/...` / `fix/...`) → PR → wait for the `checks` job → merge. Merging to `main` *is* the release: the deploy workflow publishes to Pages on push. Admin rights bypass the protection — don't use that.
- Dependabot opens weekly grouped PRs (actions + npm). They follow the normal PR flow: merge when `checks` is green.
- **Merged head branches delete themselves** — the repo has "Automatically delete head branches" on, so don't plan a cleanup step into a PR and don't be surprised when the branch is gone after merge (follow-up work restarts from `main`, it does not reuse the merged branch). The branches predating the setting are the exception; see the gotcha below.

## Architecture

- `shared/render.js` — `CardUI.renderGrid(data, opts)` renders the offer grid.
- `shared/app.js` — page bootstrap (fetch loop, status line). The page configures it with `window.DASH = { url, cmUrl, intervalMs }` and app.js **merges the two feeds** into one `results` array before rendering. `refresh()` fetches; `paint()` draws. The split matters: the source filter and the selection buttons are pure client-side state, so they repaint from the cached feeds instead of refetching both files (and making the tick boxes flicker) on every click. Both URLs are hostname-conditional: raw `data`/`data-cm` branch URLs on `github.io`, relative paths on localhost (keeps `verify-mobile.js` offline). The Cardmarket fetch is wrapped in a `.catch(() => null)` — the `data-cm` branch may not exist yet, and a failed scrape must never take the page down.
- **The header is a two-row grid and the status is a rail of labelled fields, not a sentence** (`header`/`.rail` in `ui.css`, `renderRail`/`cmFields` in `app.js`). Row 1 is mark + identity + live badge, row 2 the rail; every child names its own cell. It was one flex line with `align-items: center`, which centred each child against the tallest of them — that is how the live badge came to float in the gap beside a two-line title — and the status was a single dot-separated text node that wrapped wherever it ran out, orphaning `(1180 left)`. The label is what earns the layout: `CM CREDITS / 10 / 33 today` needs no explanatory words, so the numbers keep their room at 320px. Fields are built as data and a missing one is simply not emitted — `CM balance` exists only once a run has read the Firecrawl balance. Don't reintroduce inline separators: a `·` between clauses cannot know it has landed at the start of a wrapped line. The `≤480px` block folds the rail to 2×2 (grid, so `:nth-child(odd)` is a reliable "first in its row", with a rule between the rows) and hides the branding line — four labelled fields across 320px would leave each value about 60px, which the timestamp alone exceeds. Above 480px the rail is `flex-wrap: nowrap` with shrinkable fields **on purpose**: the divider is a `:first-child` border reset, so a wrapped line would open with a divider that has nothing before it — squeezed, a value wraps inside its own cell instead. Worst-case content (stale date-and-time stamp, four-digit balance, three-digit allowance) needs ~475px against the ~443px available at 481px, so that band is reached in practice. `verify-mobile.js` asserts the shape at every viewport; the five reviewed options are in `docs/prototypes/header-cleanup.html`.
- **The control strip (`.controls` in `index.html`) holds everything that decides what a refresh shows and costs**: the source filter on the left (free) and the selection buttons plus ⚿ and ↻ CM on the right (spends credits). Select all / Clear used to be one link inside the legend sentence, where a control that can spend the day's whole allowance read as prose. The strip's negative top margin cancels the header's bottom margin so the two meet as one band; on phones it wraps to two rows, which is what `.ctl-more` (dropped below 480px) buys. **Above 700px the header and the strip are pinned together** by the `.topbar` wrapper — the strip alone would need the header's height, which changes as the header wraps. Below 700px `.topbar` becomes `display: contents`, *not* `position: static`: a sticky element can only travel inside its parent's box, so a wrapper that still generated one would drag the sticky header off the top with it. The strip's background is opaque for the same reason the header's is — pinned over a scrolling grid, `rgba(0,0,0,.22)` showed the rows through it.
- **The source filter is client-side and per *offer*, not per card** (`opts.source` in `render.js`). A card keeps its tick box and freshness chip under a CT-only view, because both describe *scraping Cardmarket*, not the prices on screen. A card left with nothing to show falls through to the existing "watching" chips, relabelled "no Cardmarket offers" so a filtered-out card doesn't read as a fault. Filtering to one source also drops the Src column — every row would say the same thing — and `body.one-source` hands its 10% to Set so the `<col>` percentages still sum to 100. The choice persists in `localStorage` (`mtg-pricerunner.source`); that is safe only because the strip always shows which segment is active.
- **The "↻ CM" button lives in `app.js`, deliberately not its own file.** The deploy workflow stamps exactly four asset URLs with the commit SHA and `test/deploy-stamp.test.js` asserts that count, so a fifth script would mean touching the workflow, the sed guard and that test. It triggers `update-cardmarket.yml` via `workflow_dispatch` with `force: "true"`. The PAT is typed into the `#cm-token` field (shown automatically when no token is stored, reopened by the `⚿` toggle) and kept in `localStorage` under `mtg-pricerunner.gh-token` — **never put a token in the page**, the site is public and that PAT can spend real credits. A 401/403 clears the stored token so the next click re-prompts. `cloud/verify-refresh.js` pins all of this in a real browser with the GitHub calls stubbed.
- `shared/ui.css` — **the base rules are the desktop design and must not change visually.** All phone/tablet adaptation lives in `@media (max-width: ...)` blocks (1100px → 2 grid cols, 700px → 1, 480px → compact).
- `shared/cards.js` — `normalizeCards(config)` turns the paste-a-URL `config.json` entries into product objects (site, blueprintId, language defaulting). The fetchers consume it.
- **Two entry points, one per source.** `cloud/build-data.js` (CardTrader → `cloud/web/data.json`, stateless) and `cloud/build-cardmarket.js` (Cardmarket → `cloud/web/cardmarket.json`, carries the credit ledger). `cloud/fetch-cardtrader.js` and `cloud/fetch-cardmarket.js` are modules (`fetchAll(products, opts)`), not scripts — don't run them directly. Don't merge the two entry points back together: one writer per file is what keeps the 2-min job from clobbering the Cardmarket job's ledger.
- `cloud/cardmarket-parse.js` — pure HTML → offers (regex over `id="articleRow<N>"` blocks) plus `looksBlocked()`. Kept separate from the fetcher so it is unit-testable with no network.
- The deploy workflow `cp`s `shared/` files into `cloud/web/`. Copies inside `cloud/web/` (`ui.css`, `render.js`, `app.js`, `data.json`) are build artifacts and gitignored.

**`data.json` carries `meta.cardmarketCards`** — the group names config.json watches on Cardmarket. The page needs it to draw the tick boxes, and it must come from the *CardTrader* feed because `cardmarket.json` does not exist until the first successful scrape. Deriving refreshability from scraped data alone made the UI unusable exactly when it mattered: no tick boxes, so no way to start the first scrape from the site.

Data shape contract (both feeds, consumed by `render.js` after app.js concatenates their `results`): `{ updatedAt, meta?, results: [{ site, group, variant, code, productUrl, error?, fetchedAt?, offers: [{ price, priceStr, foil, condition, qty, seller, shipsToMe }] }] }`. Cardmarket offers additionally carry their own `variant`/`code`/`productUrl`, scraped per row from the all-versions page; `render.js` prefers those over the entry-level ones. `site` is `"cardtrader"` or `"cardmarket"` and drives the `Src` column (CT/CM); `fetchedAt` is set on Cardmarket results only and drives the TTL. `meta` appears only in `cardmarket.json` and is bookkeeping (`{ day, scrapes, credits, costPerScrape }`) — `render.js` ignores it. Offers are merged per `group` and sorted by price client-side. `code` is the official Scryfall set code from `config.json` and is what the Set column shows **at every width** — a code is what you compare printings by, and the full names truncated even on a desktop. The name is the link's `title`. When a Cardmarket row has a set *name* but no code, `render.js` resolves one from the card's CardTrader printings (see below) before falling back to the name, so the column still has to tolerate a long string.

## Cardmarket / Firecrawl

- **Cloudflare is why Firecrawl exists here.** Cardmarket 403s plain fetches from a datacentre IP. The old local watcher drove a signed-in Chrome over CDP; that's impossible in Actions, so `fetch-cardmarket.js` POSTs `api.firecrawl.dev/v2/scrape` (key in the `FIRECRAWL_API_KEY` repo secret) and parses the HTML it returns. Request must stay `formats: ["rawHtml"]` (the cleaned `html` format drops the ids/classes the parser matches), `onlyMainContent: false`, `maxAge: 0` (v2 otherwise serves a cached page — fatal for prices) and `proxy: "auto"` (falls back to the stealth proxy when Cloudflare bites).
- **The budget is in credits, not scrapes, and that is not incidental.** `proxy: "auto"` escalates to the stealth proxy silently, and stealth bills several credits instead of one. A scrape-counted budget would therefore under-spend the plan by ~5x or overrun it by ~5x depending on which way we guessed. Instead: read the balance, spend against `(remaining − cardmarketMinCredits) ÷ days left in period`, re-read the balance, book the measured delta, and smooth it into `meta.costPerScrape`. Don't "simplify" this back to counting scrapes.
- **The ledger lives in `cardmarket.json` under `meta`** (`{ day, scrapes, credits, costPerScrape }`) and round-trips via `--prev` off the `data-cm` branch; the day fields reset on the UTC boundary. Losing `--prev` restarts the day's allowance *and* makes every card look stale — that is a credit-burn event, which is precisely why Cardmarket got its own file and its own workflow instead of riding along in the 2-min job's `data.json`.
- **The page must day-scope that ledger itself** (`dayLedger` in `shared/app.js`). `cardmarket.json` is rewritten only when a run happens, and nothing starts that workflow on a timer — so after 00:00 UTC the published `meta` still carries yesterday's `day` and `credits` while the fetcher's counters have already reset. Reading them as today's did not just mislabel the rail: `budgetState()` greyed out ↻ CM on the morning the whole allowance was available again, disabling the one control that would have rewritten the number. Past the UTC boundary `credits`/`scrapes` therefore read as 0 and the ledger is flagged `stale`; `allowance`, `remaining` and `costPerScrape` are plan-level and kept as published, but must never be combined with a spend from another day. The stale figure is *not* given its own rail field — the rail is 2×2 at 320px and a fifth field would cost it a third row — so the provenance lives in the tooltip and in the button's title, and per-card freshness chips already answer "how current is Cardmarket?". `cloud/verify-refresh.js` stamps the fixture's `day` to the current UTC day (a fixed date would make every case exercise the stale path) and covers the rollover in its own case.
- **Deferral is stalest-first, and that matters.** When more cards are due than the allowance covers, `fetchAll` sorts the due list by `fetchedAt` ascending (never-fetched first) and takes the top N. Without that the first cards in `config.json` would eat the allowance every day and the tail would never refresh. A deferred card carries its old offers forward with **no** `error` field — it isn't a fault.
- **Don't count `fetchedAt`s to reconstruct spend.** A failed scrape costs a credit without updating any timestamp, so the explicit counter is the only honest tally.
- **A forced run (`CM_FORCE=true`, set by the site's button) ignores the TTL and the per-run limit, never the credit allowance.** `ttlMinutes: 0` already means "never reuse" in `isFresh`, so force is just that plus `perRunLimit = products.length`. Keep it that way: on-demand must not be able to outspend the plan, only to spend today's allowance sooner.
- **`CM_BALANCE_ONLY` reads the Firecrawl balance and scrapes nothing.** Reading the balance is not billed, so the site offers it as a free "Check credit balance" link — otherwise the only way to refresh that number is to spend credits. It still publishes a new `cardmarket.json` (updated `meta`, results carried forward untouched).
- **`meta` also publishes `remaining` and `allowance`** so the page can grey the button out when the day is spent. That puts the Firecrawl balance in a public file — benign (no credential), but deliberate rather than accidental.
- **The TTL, per-run limit and scrape-count budget are defaults in code, not config.** Every real run sends `force=true` (the site's button, and the workflow input's own default), which bypasses the first two; the scrape counter only applies when the balance can't be read. They were removed from `config.json` rather than left there looking like live settings — the credit allowance and the reserve are the whole story.
- **The last article row must be bounded.** Rows are delimited by the *next* `id="articleRow"`, so the final one used to run to the end of the document and absorb footer and "related products" links — one offer per card came back wearing a set lifted from page furniture. `endOfLastRow()` cuts at `</table>`/`<footer`/pagination, or at 1.5× the widest real row when there's no marker.
- **A blocked scrape looks like a successful one.** Cloudflare's interstitial is a 200 with a plausible body, so "0 offers" can't distinguish it from an out-of-stock card — hence `looksBlocked()`. On any failure the previous offers are carried forward with the *old* `fetchedAt`, so the card keeps its prices and the next run retries.
- **Cardmarket has two page shapes and the all-versions one is much cheaper.** `/Magic/Cards/<Card-Name>` lists every printing's offers in one table; `/Magic/Products/Singles/<Set>/<Card>` lists one printing. CardTrader has no all-versions equivalent, which is why `config.json` carries one CardTrader URL per printing but at most one Cardmarket URL per card — 17 Cardmarket entries against 40 CardTrader printings. Such entries are flagged `allVersions: true` and carry no `code`; config tests enforce the flag in both directions, because an unflagged `/Magic/Cards/` URL would stamp one set onto offers from every printing.
- **Not every watched card has a Cardmarket entry, and that is the cheapest knob there is.** Each entry costs a credit every time it is refreshed, so a card only worth watching on CardTrader simply has no Cardmarket URL. Those cards render CT rows with no tick box and no freshness chip — `render.js` keys both off `meta.cardmarketCards`, so dropping the entry is the whole change. The config test runs one way only (every Cardmarket group needs a CardTrader card to attach to); the reverse is deliberately unconstrained.
- **On the all-versions page the set is a property of the offer, not the entry.** `cardmarket-parse.js` gets a row's printing three ways, in order: its `/Magic/Products/Singles/<Set>/…` link (which also yields a per-offer URL), its `/Magic/Expansions/<Set>` link, then an expansion symbol's `aria-label`/`title`, restricted to tags mentioning `expansion` so a "Foil" tooltip can't be mistaken for a set. Single-product pages have none of the three, so all come back null and `render.js` falls back to the entry's own `variant`/`code`. That fallback keeps both page shapes working through one code path — don't collapse it.
- **A Cardmarket row without a code borrows one from the CardTrader printings of the same card** (`resolveCode` in `render.js`). Rows scraped before the thumbnail extraction existed have a set name and nothing else, and re-scraping them to obtain a code would cost a credit per card — so the page derives it instead, from `config.json`'s curated codes already merged into the same group. Four rules, each of which has to be *evidence*: an exact name match; `<Set> Promos` → the printing whose code starts with P (never the base set); `<Set> Extras` → the base set, which is where Scryfall keeps showcase and extended-art printings; and, only when Cardmarket is showing a single printing too, a card whose CardTrader printings are all one set. Anything else keeps the full name — a confidently wrong code is worse than the name it replaced. A resolved code also **beats** the scraped one: both sites abbreviate, and two spellings of one set in a single table read as two different printings.
- **The short set code comes from the row thumbnail, and only there.** The product image sits at `product-images.s3.cardmarket.com/<n>/<SET>/<id>/<id>.jpg`, and that `<SET>` is Cardmarket's abbreviation for the printing — the only place the page states a code rather than a name. It is what the Set column shows, at every width. It is taken **only when the row also named its own printing**, i.e. on the all-versions page: on a single-product page the config entry's Scryfall code is the curated answer, and Cardmarket's abbreviation agrees with Scryfall for most sets but not all, so it must not override it. No thumbnail = no code = the full name, exactly as before.
- **Strategy 1 has never matched a live all-versions row.** The captured specimen (`test/fixtures/cardmarket-row.html`) contains no `/Magic/Products/Singles/` link anywhere: the expansion symbol is an anchor to `/Magic/Expansions/<Set>` wrapped around the icon, and that href — added as strategy 2 after the specimen showed it — is what actually names the printing. Prefer the href over the tooltip: it's markup rather than display text, so it needs no brand stripping and can't be localised out from under us. Keep strategy 1 anyway; single-printing pages and any future markup change may bring it back, and it's the only source of a per-offer `productUrl`.
- **Test the parser against `test/fixtures/cardmarket-row.html`, not only against invented HTML.** Every synthetic test builds the markup it expects, which cannot catch the failure that mattered: a regex matching our idea of the page and nothing on the real one. That fixture was captured by a `debug=true` run (1 credit; Cloudflare makes it unfetchable from a dev box), so treat it as a specimen — don't tidy it up. It is a *partial* row: the first capture used a fixed 3000-char window and stopped before the price and condition markup, which is why the sampler now cuts at the next `id="articleRow"` instead. Assert only fields the bytes actually cover.
- **The extraction diagnoses itself.** If an all-versions card returns offers but none carry a printing, `build-cardmarket.js` logs a warning and publishes one raw article row in `meta.debug`. Cardmarket can't be fetched from a dev box, so that sample is the only way to see how the live page names a set; making it automatic means a broken extraction reports itself instead of waiting for someone to re-run with `CM_DEBUG`.
- **Cardmarket language filtering is URL-only** (`?language=7` = Japanese); the offer HTML doesn't expose it, so `offer.language` is always null there. A config test enforces the query parameter.
- `shipsToMe` is always null (renders `?`) for Cardmarket: it's only knowable when logged in, and the scrape is a guest session.

## Hard-won gotchas

- **CardTrader geo-filter:** the public website JSON (`/en/cards/<id>.json`) only returns offers shippable to the requester's IP country. That's why the fetcher uses the authenticated official API (`api.cardtrader.com/api/v2/marketplace/products?blueprint_id=`, bearer token in the `CARDTRADER_TOKEN` repo secret) — full list, no pagination. Don't "simplify" it back to the website JSON.
- **Hiding table columns:** the tables use `table-layout: fixed` with class-based `<col>` widths (`col.c-price` etc., emitted by `render.js`). To hide a column responsively, set its `col` width to 0 and its cells' padding to 0 — `display: none` on cells shifts later cells into the wrong columns.
- `shipsToMe` = CardTrader Zero (hub) eligibility on CardTrader rows; always null on Cardmarket rows.
- **The `<col>` percentages must sum to 100.** There is no Seller column any more, and it was the only one without an explicit width — the one that silently absorbed any remainder. Now every column is sized, so widening one means narrowing another by hand, in both the base rules and the 480px block — and **twice in each**, because `body.one-source` substitutes a wider Set for the dropped Src column and that variant has to sum to 100 as well.
- **The browser checks launch through `cloud/launch-browser.js`, not `chromium.launch()` directly.** CI installs the build playwright pins, so the plain launch is the normal path and the helper is invisible there. It earns its place in a sandbox (Claude Code on the web) that ships a *pre-installed* Chromium under `PLAYWRIGHT_BROWSERS_PATH`: a Dependabot playwright bump then asks for a build number the image doesn't have, and `playwright install` can't fetch it because `cdn.playwright.dev` is off the network allowlist — so both checks die on "Executable doesn't exist" and the smoke test that is *required* after any UI change simply can't be run. The helper only looks for another Chromium **after** a launch has failed, so a green CI never takes the fallback; `CHROMIUM_PATH` overrides the search. A release of browser/client skew is fine for what these checks assert — a check that cannot run at all is not.
- **A new card's Scryfall code can't be looked up from a Claude Code web session.** `api.scryfall.com` and `cardtrader.com` are both off the egress allowlist there (`curl` gets `CONNECT tunnel failed, response 403`), and `CARDTRADER_TOKEN` is a repo secret, not a session env var — yet `config.json` *requires* a code, so `test/config.test.js` fails CI without one. The working fallback is the **`keyrune` npm package** (registry.npmjs.org is allowlisted): `package/CHANGELOG.md` names every set as `<Name> (<CODE>)` and its identifiers are Scryfall codes — cross-checked against this config's own `SOA` for the Mystical Archive. Don't guess a code from the set name: `The Hobbit` is `HOB` but the Commander decks are `HOC`, and a confidently wrong code silently mislabels the Set column. **CI now checks the answer**: `cloud/verify-set-codes.js` runs on the Actions runner, where the network is open, and fails the PR if a code names no Scryfall set *or* names a real set that doesn't contain the card — the `HOB`/`HOC` case an existence check alone sails past. It degrades to a warning whenever Scryfall doesn't answer, because a gate that cries wolf gets ignored.
- **A Claude Code session cannot delete a branch, and it is not a repo-settings problem.** `git push --delete`, the REST `DELETE /git/refs/heads/...`, and the GitHub MCP server (which has `create_branch` and no counterpart) all fail — the REST call says it plainly: `Write access to this GitHub API path is not permitted through this proxy`. The block is in the agent proxy, so no GitHub permission change fixes it. Don't spend another session re-diagnosing this. **Settings → General → "Automatically delete head branches" is now on** (enabled 2026-08-27), so GitHub deletes each merged PR's head server-side, needing no agent write at all — nothing to do per PR any more. It only fires **at merge, from then on**: the 27 `claude/*` branches that predate the setting are still there (including #72's own head, merged minutes before it was switched on) and still need one manual sweep from a normal shell or the branches page — a session cannot do it, for the reason above.
- `gh` lives at `C:\Program Files\GitHub CLI\gh.exe` — shells opened before its install don't have it on PATH.
- **UI changes take up to ~20 min to appear on phones after merging.** GitHub Pages serves everything with `Cache-Control: max-age=600` and a deploy doesn't purge the CDN: an edge that re-caches the old files right after the deploy serves them for another 10 min, and the browser then caches *that* copy for 10 more. The deploy workflow stamps `?v=<commit SHA>` onto the JS/CSS links in `index.html` (CDN caches by full URL), so HTML and assets can never mismatch — but `index.html` itself is still cached, so the window applies to the page as a whole. On top of that, an already-open tab **never** picks up new UI — `app.js` only refetches `data.json`, so the header timestamp stays fresh while HTML/JS/CSS stay stale. Before debugging a "deploy didn't work" report: check the Deploy run's commit, wait out the cache window, and test in a private tab (separate cache). `data.json` is unaffected (different URL, `raw.githubusercontent.com`, max-age=300).
